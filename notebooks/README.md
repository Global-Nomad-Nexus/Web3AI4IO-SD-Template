| Notebook | Student responsibility | Independent starting point |
|---|---|---|
| [01_On_Chain_Tutorial.ipynb](01_On_Chain_Tutorial.ipynb) | Student A leads, B reproduces | Archived original event fixtures |

Download each file using GitHub's raw-file download control. Upload the .ipynb into Colab, or use the root README's Colab buttons, then **File → Save a copy in Drive**. Rename the copy with the project, component and author/version. Share the Drive copy with the coauthor and supervisor. Editing Drive does not update GitHub; download the edited notebook and commit the reviewed version when ready.

Read the Markdown explanations before code, start in a fresh CPU runtime, and run in order. No API key, GPU or Drive mount is needed for the teaching examples. Code is retrieved from a full pinned commit and all data operations then run offline. The demo depends only on Python's standard library plus IPython for notebook display. Each notebook has the requested eight parts, source/dictionary URLs, code-file links, expected outputs, author worksheets, validation, receipt and optional output download.

All cells are supplied unexecuted for clean student copies; measured validation evidence is in [the receipt](../docs/validation_receipt.md). The executed examples are synthetic, not empirical project results. To adapt, complete the author prompts and source/validation worksheets, implement the actual pipeline, update all manifests and reference outputs, then pin a reviewed code commit. Editing AUTHOR_INPUT metadata alone does not implement research acquisition. The example RUN_MODE guard stops unsupported mode changes.

Integration preserves unmatched cases and requires an explicit relationship/time policy. It can run before either other notebook by acquiring their archived component outputs. Both authors must agree changes to shared keys, units, time semantics and release compatibility.
