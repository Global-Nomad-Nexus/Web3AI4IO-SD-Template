# Manuscript evidence map

Use the supervisor's Scientific Data Overleaf workspace for writing. This folder contains instructions rather than an invented paper. Consult the current [official guidance](https://www.nature.com/sdata/submission-guidelines) and the [requirements crosswalk](../docs/requirements.md).

| Manuscript area | What both authors should supply |
|---|---|
| Title and abstract | Actual data type, scope and reuse purpose; no unmeasured impact or novelty claims |
| Background and Summary | Why the separate source resources and their integration matter; users, prior sources and limitations |
| Methods | Separate on-chain and off-chain collection/processing subsections, then shared linkage and time-alignment methods; exact input versions and attrition |
| Data Records | File inventory and relationships for all three components, formats, identifiers, field meanings and access |
| Optional Data Overview | A compact orientation to the released data; keep substantial hypothesis-driven analyses in the research paper |
| Technical Validation | Source checks, independent quality evidence, linkage-error assessment, coverage and sensitivity; distinguish them from software tests |
| Optional Usage Notes | Practical access and reuse guidance, with links to all three tutorials |
| Availability and references | Matching data/code versions, suitable repository identifiers, source citations and restrictions |
| Authorship and declarations | Actual contribution record, funding, conflicts and relevant ethics information; follow current portal instructions |

Keep `metadata/result_index.json` synchronized with final table/figure labels and each reported number. Track manuscript claims with `templates/VALIDATION_PLAN.md`. Do not present any of this repository's synthetic counts as project findings.
