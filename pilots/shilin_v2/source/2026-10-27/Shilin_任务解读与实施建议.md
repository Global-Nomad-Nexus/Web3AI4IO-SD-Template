## 任务二：尽早验证 Polymarket 历史预期是否可用

### 怎么做

1. **先建候选市场目录，不下载全库。** 调查老师指定的类别：经济与利率/通胀预期、SOL、BNB、Pump.fun 上市/公开募资/收入、Base 官方发币。记录关键词、查询日期、过滤条件、分页及纳入/排除理由；开市和已关闭市场都要检查。
2. **按用途筛选。** 每个候选检查经济含义、时间重叠、真实历史价格、分辨率和有效变化。分为：

   | 类别 | 纳入条件与处理 |
   |---|---|
   | 可用于预期—活动展示的市场 | 与发行或生态有明确联系、在研究窗口内有有效历史，且数据变化足以支持所展示的用途 |
   | 背景目录市场 | 时间不重叠、历史缺失、变化不足或关联间接；保留规则与来源，说明限制，不强行分析 |

3. **先取得少量真实记录。** 优先选择与现有七日窗口重叠的市场，通过官方 API 获取 event/market/condition/outcome ID、outcome 标签、问题、完整结算规则、开市/结束/结算时间、状态与结算结果、历史价格、可获取的交易活动及来源。保存原始响应、获取日期、协议/接口版本和实际价格分辨率。当前价格和当前订单簿不能代替历史记录。
4. **建映射表，说明关联层级。** 每条映射保存目标 ID、证据和有效时间窗，使用以下四类：

   | 链接类型 | 表达什么 |
   |---|---|
   | 代币身份 `verified_token_identity` | 规则和地址证据可唯一核实的特定代币 |
   | 平台 `platform` | Pump.fun 等平台的整体上市、募资或收入事件 |
   | 链生态 `chain` | SOL、BNB 或 Base 生态背景 |
   | 共同经济事件 `shared_economic_event` | 同一次利率决议、通胀发布等三链共享背景 |

5. **明确价格与时间规则。** 区分服务返回的历史价格、成交价、midpoint 等，使用“市场预期代理”表述。逐币只连接创建时已经可见的价格；时间桶也不得包含创建后的信息。日度展示可使用当日开始前最后有效价格，保留源时间和陈旧标记。不同题目、阈值、期限分开保存；已结算结果不能延续成后续实时预期。
6. **记录缺失与覆盖。** 区分无匹配、不重叠、历史不可得、请求失败、价格陈旧等，不填成 0 或 0.5。分别统计直接身份匹配的代币占比，以及有有效背景预期的链—平台—日占比；两者不能混称匹配率。

**两条必须守住的边界：** Polymarket outcome ID 不是发行代币地址；“任一合格 Pump.fun 代币上市”的价格不是每个代币的上市概率。历史募资或收入题目须核实所属时期，不能跨期套用。

实施入口：[市场发现](https://docs.polymarket.com/market-data/discover-markets)、[市场详情](https://docs.polymarket.com/market-data/market-details)、[历史价格与订单簿](https://docs.polymarket.com/market-data/prices-order-books)。

### 预期结果

交出**候选目录、规则记录、历史价格表、映射表和覆盖报告**。P1/P2 的真实连接已经建立；P3 按上述全部指定类别继续调查，不只复用一个 Fed 市场。逐类别记录 active/closed 查询、子市场/outcome、分页与停止原因；逐 outcome × 正式窗口核对规则对象/时期、时间重叠、真实历史、分辨率、有效锚点与用途，报告候选、核对、历史取得、可连接及受限/不可用数量。无同窗历史的保留为目录，价格不变的保留其实际用途，不按变化大小挑题。

P3 沿用桶结束严格早于创建/日初锚点、主陈旧度 24 小时和 12/48 小时敏感性规则。价格构造与历史规则版本仍未核实时，保持“受限回溯展示”，不升级为已认证的事前预测特征。直接代币身份、平台、链生态、共享经济事件分开报告，允许某类为零；背景覆盖率不能替代直接身份匹配率。
